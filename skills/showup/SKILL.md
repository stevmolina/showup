# Show Up

Create content from work that already happened. Treat social content as an output of the work log, not a separate task system.

## Route the request

- For voice matching or rewriting, read [Steven's voice](references/steven-voice.md).
- For turning GitHub, Linear, Codex, Notion, or Calendar activity into ideas, read [Work to content](references/work-to-content.md).
- For Typefully drafts, scheduling, publishing, replies, or account operations, read [Publishing](references/publishing.md).

Read every reference needed by the request before acting. A request may use more than one path.

## Core workflow

1. Gather the user's source material and preserve links to the evidence.
2. Find the human story before choosing a platform or format.
3. Draft in Steven's current voice. Use the technical details as proof, not as the opening.
4. Keep claims traceable to the source material. Mark inference and uncertainty plainly.
5. Save to Notion or Typefully only when the user asks for that write or the requested workflow clearly includes it.

## Boundaries

- Personal GitHub, Linear, Notion, Calendar, and Codex activity are the default source pool.
- Plane contains Resorsi work. Treat Plane and other client material as private unless Steven explicitly selects specific material for public use.
- Drafting and saving a private draft are reversible. Publishing, scheduling, replying, liking, reposting, deleting, and sending DMs need explicit authorization for the exact account and content.
- Strip credentials, private URLs, customer information, and unreleased commercial details before creating a shareable draft.

## Done

The result is complete when the draft has a clear human point, sounds consistent with the voice reference, includes only supportable claims, fits the selected platform, and any requested write returns a verifiable page, draft, or post URL.
