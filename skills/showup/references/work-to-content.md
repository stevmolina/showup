# Work to content

Use this reference when collecting work activity, maintaining the Notion content system, producing a digest, or finding stories in project evidence.

## System

```text
real work
  -> evidence and decisions
  -> chronological work log
  -> story candidates
  -> Notion Content Inbox
  -> human review
  -> Typefully draft
```

The system must not create recurring Todoist tasks. Normal work should leave enough evidence for the next stage to run.

## Sources

Prefer evidence that already exists:

- GitHub commits, pull requests, releases, README changes, and demos
- Linear issue changes, comments, milestones, and project outcomes
- completed Codex tasks and their final summaries
- Notion decisions, raw observations, and project notes
- Calendar sessions as context for when work happened

Automatic sources record what happened. Steven supplies the part software cannot know, usually why a decision mattered, what felt frustrating, or what surprised him. Ask for that missing context only when it materially changes the story.

## Select meaningful events

Keep events that contain at least one of these signals:

- a decision with a real tradeoff
- a problem others recognize
- a failed attempt or changed mind
- visible proof of progress
- feedback that changed the work
- a result that contradicts the original expectation

Skip mechanical activity that adds no story, such as dependency bumps, formatting-only commits, routine status changes, or raw command history.

## Build a story candidate

Record:

- what happened
- why a person in tech might care
- the tension, decision, or surprise
- evidence URL
- project and date
- whether it is safe to share

Then apply [Steven's voice](steven-voice.md) and create a concise candidate. Do not invent emotion or intent from technical evidence.

## Review output

For a daily or weekly digest, return a compact list of evidence-backed moments. Rank them by human relevance, freshness, strength of proof, and shareability. Draft only the strongest candidates unless Steven asks for breadth.
